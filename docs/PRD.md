# GameWise AI 产品需求文档

本文件定义产品需求与验收边界；实现状态见[PLAN](../PLAN.md)，当前接口和检索设计见[DATA_DESIGN](DATA_DESIGN.md)。需求存在不表示已经实现或验收。

## 1. 产品目标

面向普通玩家提供多游戏、多版本的攻略、机制解释与比较助手，针对通用模型混淆游戏规则、编造细节及缺少来源的问题，通过检索资料支持回答。统一提问入口处理事实查询与比较，不另建比较页面或接口，不承诺消除全部幻觉。

## 2. 首批范围

| 游戏/分支 | 当前定位 | 资料状态 |
| --- | --- | --- |
| 三国杀 OL、十周年、移动版 | 首批 MVP 验证技能查询、解释、跨服比较及短追问 | 已有本地批量待审资料；登记、采集、入库、审核和可回答分别统计，不宣称全量或线上最新 |
| 黑暗之魂 3 | 延后，保留早期清单实验 | 未建立当前问答支持 |
| 艾尔登法环 | 延后 | 未建立真实知识库 |

优先完成可演示、可测试、可解释的工程闭环。全武将全系列是后续覆盖目标，不阻塞原型收尾；正式准入与最终演示范围仍需审核，不能把有限案例称为完整产品。三服跨服对照属于首批目标；跨游戏和完整历史版本比较延后。

## 3. 用户需要的行为

- 输入自然语言问题，由单个 LLM 选择只读工具。三国杀问题未指定服时，按已配置三服分别查询；指定服时只查对应范围。
- 人物比较或推荐未指定系列时，考虑有来源关联的各系列；明确具体条目/系列时只查所选，不悄悄缩为标准版。武将包、系列、玩法模式分别处理，不凭前缀推断规则。
- 比较分别取得各侧资料、标明归属。原文相同如实说明；一侧缺资料时保留另一侧结果，缺口不能说成游戏中不存在。
- 网页展示 Markdown 答案、可展开的来源原文及查询过程；当前支持最近两轮成功问答的短追问，新对话或刷新清空，不承诺长期记忆。
- 身份适配、强度、技能设计体验和人物还原是不同评价维度。可以依据已查技能、规则及社区框架给倾向性建议，但不伪造胜率、排行榜或角色背景；专家级强度排名不是首版门槛。
- 技术故障与资料不足分开；资料冲突已识别时披露双方依据，不承诺自动发现所有语义矛盾。

## 4. 证据与范围边界

资料至少可定位来源、游戏范围、采集/修订信息、内容指纹及审核限制。页面日期不是游戏补丁版本，人物关联不代表规则共享，同名技能不能跨服、系列或模式补齐。未知版本不默认最新或通用。

原始资料、整理正文与索引分开；转换或入库成功不等于内容已审核。来源可公开阅读不等于允许复制分发，资料使用范围及外发需确认。未上线条目也可收录，但上线状态与审核状态分别保留，不能因网页存在就说已实装。

重要事实尽量关联本轮检索来源。程序检查引用存在性及归属，人工核对原文是否支持结论；漏引用可保留回答并提示，不伪造出处或宣称已验证。历史回答用于理解追问，不自动成为本轮证据。

## 5. 技术与运行边界

React + TypeScript + Vite；Python + FastAPI + Pydantic；结构化资料优先 SQLite，原文 Markdown/JSON；可配置 LLM API 与测试替身。当前在线检索和向量实验的区别见DATA_DESIGN。

应用本地运行，不建设云服务器、登录、多 Agent、重型向量数据库或资料管理后台。具体外部模型、服务、依赖、费用和发送范围须确认；通用 API 方向不授权任意费用。

不纳入首批：全游戏覆盖、自动操作游戏、实时画面理解、模型训练、全量技能交互推演及大规模实战统计。自动更新、全文网页搜索等未实现能力不能写成现有功能。

## 6. 接口要求

| 接口 | 当前行为 |
| --- | --- |
| GET /health | 检查服务存活，不代表模型或资料可用 |
| POST /api/ask | 当前问题和最多两轮历史文字；返回答案、来源、查询摘要和错误；密钥/模型地址/资料路径不由网页提供 |

GET /api/catalog为原计划中的目标接口，当前未发布；模型目录工具不等于HTTP目录接口。具体字段以Pydantic/OpenAPI和DATA_DESIGN为准。

## 7. 验收与评测

程序检查、真实模型效果和用户验收分别记录。首版应核对正常问答、明确范围/澄清、资料不足、至少一个真实跨服技能对照、引用归属和服务故障；前端类型/组件/构建检查不能代替真实端到端验收。新增游戏的合成测试不代表该游戏已有真实资料。

### 已确认的12道开发题

用户于2026-11-21确认以下题目及判据，D01–D10为核心检查，D11–D12为探索推荐，不规定冠军。以下保留原问题和必要判据，本次文档整理不改题、不改变验收条件。已看过的案例属于开发集，不是独立评测。

| ID | 两组使用的相同问题 | 必要事实或预期行为 |
| --- | --- | --- |
| D01 | 三国杀OL经典模式，界曹操的奸雄有什么效果？能直接回血吗？ | 受伤后可获得造成伤害的牌并摸一张；技能没有直接回血，不泛化为取得伤害来源的任意牌。 |
| D02 | 三国杀十周年经典模式，普通孙坚的英魂何时发动？已损失2点体力时有哪些选择？ | 准备阶段、已受伤、选择其他角色；X为已损失体力，分别摸2弃1或摸1弃2；不能写成孙坚自己执行。 |
| D03 | 三国杀移动版经典模式，界诸葛亮能看几张牌？什么时候能再次观星？ | 通常5张，存活角色小于4时改3张；将这些牌全部置底后，可以在结束阶段再次发动，不是无条件两次。 |
| D04 | 三国杀OL经典模式，魔曹操的霸朝在什么时候发动？谁可以被其伤害，谁会入魔？ | 出牌阶段开始；其他角色可选择交牌，可伤害未以此法交非基本牌的一名角色；选择自己时自身入魔，当前手牌本阶段使用不受次数/距离限制，不是全队入魔。 |
| D05 | 对照三国杀OL和移动版经典模式的普通孙坚：英魂的触发和两种效果有什么异同？ | 分别取两服原文；本地样本触发、X与两种效果基本一致，允许指出表述差别，不为展示比较而编造规则差异。 |
| D06 | 三国杀OL经典模式，普通刘备和界刘备的仁德有什么区别？一次交出两张牌是否必须再发动一次才能触发第二张牌的效果？ | 普通版第二张仁德牌回复1体力；界版每名角色阶段限一次、第二张可视为使用基本牌。计数是给出牌的张数，不是发动次数；界版不能直接改成必然回血。 |
| D07 | 三国杀OL普通诸葛亮的经典模式和1V1模式，观星的张数有什么不同？ | 经典X为存活角色数且至多5；1V1为2；标明模式，不借用界诸葛亮固定5/3张或二次观星效果。 |
| D08 | 按本地保存的三国杀规则集3.0历史参考，失去体力和受到伤害有什么区别？仅失去体力是否等同于受过伤害？ | 都会扣减体力，但失去体力无来源、不进行伤害结算；不等同受到伤害。明确历史参考边界，不延伸未查技能裁定。 |
| D09 | 按本地保存的三国杀规则集3.0历史参考，如果全部伤害都被防止，还算受到过这次伤害吗？ | 视为来源未造成、目标未受到这次伤害；区分全部防止与部分减少，不扩展成所有相关事件都不发生。 |
| D10 | 请给出三国杀OL统率版本界曹操的技能。 | 本地精确查询该模式当前无记录；系统应说明未收录，不能拿经典技能顶替，也不能说游戏中不存在。普通模型若回答，按可核实来源另审，不因不了解我们的库而机械判错。 |
| D11 | 三国杀ol最强诸葛亮 | 按OL有来源各系列讨论，事实不混用，比较维度及代价明确；允许条件推荐或说明不足，不预设谁第一，不虚构胜率/共识；仅查普通版不得冒充全部。 |
| D12 | 三国杀OL里刘备、曹操谁适合做主公？ | 同服各系列按需分析，主公技只是因素之一；事实与推断分开，未查配将能力不凭记忆补写；给出有前提建议，不规定刘备或曹操必胜。 |

核验基于本地快照：技能按来源ID、服、条目、模式及技能名定位，原文指纹/locators回查原始页面；规则片段位于`data/local/embedding-preview.local/index-v2/chunks.json`，D08参考description/loselife，D09参考damage。页面更新不自动替换评测依据；历史规则3.0不代表三服现行通用裁定。

### 人工评分与对照约定

| 记录项 | 判定方式 |
| --- | --- |
| 事实曲解 | 2＝必要事实正确完整；1＝无关键错误但漏必要细节；0＝关键条件、对象、次数、数值或效果错误/编造。不需要事实作答的项目记不适用，说明理由。 |
| 越界推断 | 通过＝分析基于已查事实，前提和局限明确；失败＝把可能性当定论、虚构配将能力/胜率/共识，或用不相关文章支撑结论；纯事实题无额外分析记不适用。 |
| 范围与覆盖 | 通过＝覆盖所问服、系列和模式且各自归属清晰；失败＝混用或漏一方却声称完整。资料缺失被如实说明时另记“未完成但已披露”，不能当作已完成比较。 |
| 引用存在性 | 仅系统组检查编号是否属于本次实际返回内容、能否解析映射；另记格式未识别和捏造编号。普通模型无引用记不适用，不因没访问知识库直接判错；虚构来源单记。 |
| 引用语义支持 | 人工看关键断言是否得到相邻引用原文支持；通过、部分或失败，附具体原文与错误句。与编号存在性分开，不能靠程序声称语义已验证。 |
| 调用故障与资料不足 | 超时、限流、鉴权/格式/查询错误与真实无资料分开记录；故障轮无答案不当作模型事实0分，但必须计入尝试数和完成率。D10同时检查是否诚实说明当前覆盖。 |

不合成单一总分。普通组只给用户问题，不带项目提示、资料或工具；系统组用当前流程，保持同一基础模型、问题和共同配置，披露额外提示/资料差异。该比较不能单独证明ReAct收益。

保留每题原始回答、资料快照、检索结果、耗时、用量、故障和评分理由；缺答案不计事实0分，但计入尝试数与完成率，不挑最好一次或隐去重试。普通组无引用记不适用，伪造来源另记。首次每题每组一次仅为探索，重复次数、真实API及预算另行确认。

独立题集和评分门槛需在调参前冻结；看过独立结果再修改的版本另记实验。不得以替身通过、单题表现或检索命中率宣称整体回答准确率提升。已运行结果和未完成项只在PLAN汇总，原始记录留在本地，不在本文件逐轮追加。

## 8. 后续扩展

在用户确认后再开展更多游戏、历史版本映射、资料更新管理与检索方案接入。优先复用通用核心、配置及小型适配，不预建复杂框架。14阶段仅表示实施顺序，不是硬性工期；执行规则见[AGENTS](../AGENTS.md)。
