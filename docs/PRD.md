# GameWise AI 产品需求文档

状态：初稿，产品方向已确认；技术选型与首批具体游戏、版本待审查。

## 1. 项目目标

为普通玩家提供容易使用、能够追溯来源的多游戏 AI 攻略助手。玩家可以询问道具、Boss、技能和游戏机制，并在明确游戏及版本的前提下比较差异。

系统应通过检索可靠资料支持回答，减少凭空编造；后续通过固定测试题集与普通 LLM 进行对比，验证实际效果，不预设系统一定更好。

## 2. 目标用户与需求

| 用户场景 | 用户需求 | 期望行为 |
| --- | --- | --- |
| 查询道具 | 了解用途、条件及相关限制 | 返回资料支持的说明和来源 |
| 挑战 Boss | 了解机制与应对思路 | 区分已确认机制和策略建议 |
| 查询技能或规则 | 理解触发条件、效果和交互 | 按指定版本解释，不混用规则 |
| 比较游戏或版本 | 理解相似内容及差异 | 明确比较对象、维度和各自来源 |
| 信息不充分或存在冲突 | 知道答案是否可信 | 提示缺失信息、版本歧义或来源冲突 |

## 3. 覆盖范围

- 产品方向覆盖魂系游戏和三国杀不同版本。
- 首批只选择少量、可验证的资料，逐步扩展；不承诺一次覆盖全部游戏和版本。
- 首个游戏、三国杀的具体版本，以及跨游戏比较的具体对象，均需用户确认。
- 优先本地运行；是否使用外部模型 API 待确认，不要求部署云服务器。

### 游戏登记与知识库状态

“已登记支持的游戏”是指已由用户确认名称、版本和支持范围，并登记为产品目标的游戏。登记不代表已经收集可靠资料，也不代表能够回答该游戏的所有问题。

“已建立可靠知识库的游戏”是指其特定版本、特定主题的资料已经审核，来源可追溯，并通过对应查询验证的游戏。此状态仅适用于已验证的覆盖范围，不意味着拥有完整攻略。

| 类别 | 当前状态 | 含义 |
| --- | --- | --- |
| 规划覆盖方向 | 魂系游戏、三国杀不同版本 | 产品方向已确认，具体游戏与版本待选择 |
| 已登记支持的具体游戏及版本 | 暂无 | 用户确认首批具体对象后再登记 |
| 已建立可靠知识库的游戏及版本 | 暂无 | 尚未导入、审核资料或验证问答 |

后续按“游戏名称、版本、登记状态、知识库状态、已覆盖主题、资料来源、已知缺口”维护记录。对于仅登记但没有可靠资料的游戏，明确提示尚无知识库支持；对于已建库但超出覆盖范围的问题，说明资料不足，不推断为已支持。

## 4. 最小可用功能

以下按独立小功能逐步实现，每次完成测试与用户审查后再继续。

1. **资料基础**：能够导入少量经过人工检查的资料，记录游戏、版本、来源及资料内容。
2. **单游戏查询**：针对一个已确认的游戏与版本，支持基于资料回答一个主题的问题，再逐步扩展至道具、Boss、技能和机制。
3. **来源与不足处理**：回答展示可追溯来源；无资料支持时明确表示无法确认；关键版本缺失时请求补充。
4. **版本隔离**：引入第二个资料范围，确保查询不会混用不同游戏或版本的事实。
5. **基础比较**：比较两个明确指定的游戏或版本中的一类内容，按统一维度展示差异与来源。
6. **基础评测**：用固定题集对比普通 LLM 与系统，记录答案、评分依据与运行条件。

首个可测试切片为“一份人工审核资料、一个明确游戏版本、一个主题的有来源问答”。比较和评测在此基础上增量开发。

## 5. 资料和回答要求

- 优先使用官方说明、游戏内文本与有版本标记的可靠资料；社区资料作为补充并标明性质。
- 资料至少记录标题或标识、游戏、版本或适用范围、来源位置及采集日期；网页资料保存原始链接，本地资料保存定位信息。
- 回答中的关键事实应有对应来源，不能仅附一个与结论无关的链接。
- 资料冲突、时效不明或证据不足时，说明限制；策略建议与确定事实分开表述。
- 不承诺完全消除错误，以可检查的来源和测试降低错误风险。

## 6. 验收方式

| 能力 | 最低验收要求 |
| --- | --- |
| 查询 | 在首批人工审核示例中回答关键事实，且能定位支持它的资料 |
| 来源 | 引用确实存在，并支持相邻结论 |
| 不足处理 | 对缺少证据的问题不编造，对影响答案的版本歧义进行澄清 |
| 版本隔离 | 对同名内容的版本差异测试不混用事实 |
| 比较 | 双方游戏及版本明确，比较维度一致，各自有资料支持 |
| 本地运行 | 在用户本机按文档完成启动与一次验证；外部服务依赖明确列出并经确认 |
| 评测 | 相同题集、基础模型与可比较配置下记录两种方案的结果，披露系统额外使用的资料 |

具体题量、准确率目标和性能门槛在题集建立后由用户审查确定。

## 7. 暂不包含

- 云服务器部署、账户系统、付费功能和多人协作。
- 登录、多 Agent 编排及其他超出 MVP 必要范围的复杂功能。
- 自动操作游戏、实时画面分析或游戏内插件。
- 大规模网页抓取、全游戏数据库或模型训练。
- 未经验证的全自动攻略生成，以及复杂前端界面。

## 8. 待确认事项

- 首个魂系游戏、三国杀版本与首批查询主题。
- 模型使用方式、资料存储和检索方案。
- 最初交互入口及本机运行环境。
- 允许采用的资料来源及其使用限制。
- 评测题集规模、评分流程和验收目标。
