# GameWise AI 长期项目背景

记录产品方向、关键取舍和学习目标，用于跨任务协作；不维护逐次进度，也不自动授权后续实现。当前状态见[PLAN](../PLAN.md)，业务要求见[PRD](PRD.md)，执行规则见[AGENTS](../AGENTS.md)。

## 1. 产品定位

GameWise AI是面向普通玩家的多游戏、多版本、基于证据的攻略及比较助手，解决通用模型在具体道具、Boss、技能及规则问题上容易混淆范围、编造细节和缺少来源的问题。回答可以分析和推荐，但须分清事实、社区观点与推断，不承诺消除幻觉。

问答和比较共用自然语言入口，不拆成两个产品。人物比较应考虑请求范围内有来源的系列，不默认只讲标准版；明确具体条目时保持范围。身份适配、数值强度、设计体验与人物还原分别判断，主观结论不伪装成统计排名。

## 3. 技术方向

前端React + TypeScript + Vite；后端Python + FastAPI + Pydantic；SQLite存结构化资料，Markdown/JSON保存原文与处理结果；LLM通过可配置API接入并提供测试替身。当前工具、检索与模型参数详见[DATA_DESIGN](DATA_DESIGN.md)，不在本文件复制运行配置。

本地优先，不建设云服务器、账号登录、多Agent或重型基础设施。保持模块简单：通用处理、来源适配、数据库存取、检索和模型调用各有边界，不为未来游戏预建空框架。

资料按特点组合三条路径：规则/人工提取后校验入库；杂乱文本可由LLM辅助提取指定字段；长文保留原文、切分并建立检索索引。LLM辅助整理目前只有接口与替身，不能说成已接真实服务；向量化不等于摘要或事实审核。

用户已确认本地E5-small、Sentence Transformers及CPU PyTorch用于首轮检索实验；新增模型、服务、依赖或外发费用仍需确认。外部回答API可能联网和收费，不能与本地embedding计算混为一谈。

## 4. 六项工程学习目标

1. 将产品需求拆成里程碑、小任务、实现与验收标准，明确用户和Codex的分工。
2. 从需求推导业务规则、数据结构、接口及测试；陌生技术先做小规模验证。
3. 比较语言、框架、数据库与模型方案，保留技术取舍依据，不补造历史理由。
4. 用通用核心、游戏配置与小型适配支持扩展，理解职责与依赖方向。
5. 编写目标清楚的开发提示词，维护持续有效的工程文档，不依赖聊天上下文。
6. 实践Git分支、Commit、Pull Request、审查与安全回滚；学习目标不等于已授权操作。

每个任务选择相关学习点，用具体输入输出帮助用户理解代码，而不是让用户只点批准；不要求先学完整个技术栈。
